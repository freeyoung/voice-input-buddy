## P1 项

| 编号 | 复核结论与处理 |
| --- | --- |
| A1 | 容量缺陷成立。FIFO 消耗 pre-roll 时，live 差值不会同步下降，原半秒 live 限额可拒绝后续语音。现在为整段积压保留 pre-roll 对应的容量预算，直到整个队列归零才释放；总上限为 80,000 + 8,000 个采样，正常无 pre-roll 仍为 8,000。测试连续模拟 5 秒 FIFO 消耗与实时到达，不丢批次且不突破边界 |
| A2 | 引擎不可播放时 enqueue 拒绝、恢复仍等 1 秒的路径成立。活动音源且引擎不健康时改为立即请求恢复；健康设备事件仍走原有保护。不宣称消除了实际硬件重建耗时中的所有丢音，亦未新增无限应急队列。测试验证实际恢复入口请求的延迟为 0 |
| In1 | 固定时限恢复旧剪贴板确有慢接收端读错内容的风险。按已确定的交互调整：成功提交后保留短语；设置页与状态菜单提供“恢复原剪贴板”，快照只保留在有界内存中。只有未提交粘贴 key-down 时才即时回滚；key-up 失败不能把已经排队的 Cmd-V 当作未发送。后续新复制内容始终优先，不覆盖、不自动恢复。测试包含 5 秒延迟读取、部分按键提交、立即回滚、多格式手动恢复、连续短语和失败后的原始恢复点 |
| In2 | AX 候选缺少结构性安全字段成立。补采集 subrole / protectedContent，并在 composer、记录目标匹配和文本候选评分中拒绝安全字段，不依赖 password/PIN 等文案。测试使用带强 composer 语义的安全字段，仍必须拒绝。原报告从“可能误聚焦”推导到“已注入密码框”的后果未实测；目的地协调器原本还有独立的安全校验 |
| App1 | 锁失败后可无锁初始化运行时的 fail-open 路径成立。现在锁失败和无法确定锁路径时都退出，不初始化蓝牙、音频或事件 tap；保留 stderr 错误。文件锁的权限、符号链接与并发排斥测试仍通过 |

## P2 项

| 编号 | 复核结论与处理 |
| --- | --- |
| A3 | 短 drain 的定时器可强制结束同组长 drain，成立。每个请求记录绝对截止时间，加入请求时使旧定时器失效，按整组最晚截止时间排空；无限等待请求不被后来有限期限截断。测试覆盖 2 秒 + 0.75 秒及无限等待 + 有限等待 |
| A4 | “缓冲为 0 因而无人唤醒”不成立。计数降到 0 的同一临界区已记录 completionGeneration，随即排队到主线程执行 finishDrainedSessionIfNeeded；此窗口内加入的新 waiter 由该回调一起完成。报告遗漏了这个已排队回调。保留原有归属规则，避免把新音频会话提前结束 |
| A5 | 纯 Objective-C 边界确实不提供 C++ catch；硬件冲突必然抛 C++ 的说法未验证。改为 Objective-C++，嵌套捕获 NSException 与 C++ 异常；新增仅测试依赖的 C++ 抛异常 fixture。**不能捕获 Mach 异常、内存破坏或进程信号**，报告将这些混为一谈不准确 |
| A6 | 每次通知都重置静默窗口会推迟恢复，成立。非紧急通知合并到第一个已安排的恢复，不反复后移；活动故障优先立即恢复。有限的多接口通知突发不应直接称为“永久饿死” |
| A7 | 音量写入逻辑存在，但当前产品选定 UID 固定为自研 BuddyMic，报告关于用户选择外部 BlackHole 混音的实际触发前提不符合当前设置。仍收窄写入白名单：只修复自研驱动，不再改第三方 BlackHole 音量；保留第三方设备的只读诊断。测试验证 foreign BlackHole 不进入修复 |
| In3 | 仅凭键码 63 剥离所有 Fn 标志过宽。共享修饰键策略现在只在 numeric-pad 导航装饰且键码 63 未按下时去掉 Fn；无导航装饰的 Fn 始终保留，粘贴等待/拒绝。外接键盘的具体设备行为仍需真机验证；不能保证仅靠系统聚合标志区分所有 Fn + 导航组合 |
| In4 | 两次同步释放失败后无后续清理，成立。增加有界异步重试与按键所有权：未确认释放前不再次按下相同修饰键；旧任务不能释放新所有者。测试验证失败后的异步成功与新按下被阻止。报告“永远卡住、必须拔键盘”的结论过强，事件提交也无 WindowServer 接收确认 |
| In5 | 普通按键确实使用 HID-system 事件源且合并未规范化标志。改用 privateState，并复用上述修饰键规范化，保留真实物理修饰键。没有声称已复现全局输入表污染 |
| In6 | 未复现“空剪贴板必然失败”：清空命名剪贴板的现有参数化测试已通过。pasteboardItems 为 nil 也可表示读取不可用，不能无条件当空后覆盖原内容。保留拒绝不可读快照的保护；成功空快照仍支持正常插入和恢复 |
| In7 | 禁用时 tapReady 立即为 false，但生产所有者此前仅在重试停止后收到通知，存在状态滞后。现在第一时间通知所有者，生产映射立即停止并显示中断状态，避免无过滤时继续映射。单独使用时的既有恢复仍有界。测试验证无需等待重试即可通知 |
| App2 | 未证明“旧进程清理通常需 400–800ms”就是缺失实例的锁冲突窗口；旧实例仍被系统列出时根本不会进入此退避分支。作为有界加固，预算由 300ms 增至 1.2 秒；测试在第 4 次重试才释放锁并验证获得锁，同时验证总次数上限，不宣称覆盖所有升级重启时序 |
| App3 | 退出等待期间新语音仍可获准的缺口成立；死锁/断言后果无复现。接受退出时立即关闭新会话准入，公共 begin 入口与迟到的输入源激活回调也检查终止状态；保留既有释放/排空流程。测试验证 stop 前蓝牙准入已关闭且不能进入 streaming |
| App4 | 未发现报告所称的无限等待：Fn 释放已有 1/2/4 秒重试上限，失败耗尽也会完成回调，原回归测试锁定该路径。音频 drain 同样有截止。主队列若被外部同步调用阻塞，额外的主队列定时器也不能兜底。保留当前安全释放预算，不加可能抢先退出并遗留按键状态的任意 watchdog |
| App5 | Cmd-V / 菜单 paste 未被当前物理编辑检测覆盖，成立；仅粘贴文字仍不能单独通过，原有 voice samples/session ended 前提仍存在。覆盖物理 Cmd-V 和上下文菜单粘贴，并允许来自语音工具的合成粘贴；测试区分这些来源 |
| App6 | 物理 Return/Keypad Enter 与遥控器确认键不能仅靠当前策略区分。正常原生过滤仍会吞遥控器按键，所以“必然误判”未复现。策略加固为不把 Return、Tab 本身当有意义的手动打字；真实字符和删除编辑仍记录。测试覆盖两个确认键码 |
| App7 | 每次下载/解压进度回调重建整个视图，成立，但不是每个 TCP 包都对应一次委托回调。进度改为更新既有 indicator / 文本，阶段或语言变化才完整重建；测试验证进度控件对象复用 |
