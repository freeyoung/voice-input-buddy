# 语音会话与输入边界二次核验

基线：main `d91e420`。编号按本轮提交的 15 项问题排列。修复位于同一个 PR，各独立问题分别提交；不将推测性的系统行为当作已复现结论。

| 编号 | 结论与处理 |
| --- | --- |
| 1 多输入源互斥 | 成立。新增 `canAcceptNewVoiceSession(from:)`，三个入口在修改会话、配置音频或注入按键前检查其他通道的活动、待启动、停止收尾和激活状态；Apple 同时拒绝另一台设备加入。原有同一设备快速重按和手机延后重启仍保留。测试覆盖活动 BLE、待配置 BLE、Apple 收尾、手机待激活/活动和跨来源激活等待。原有 `VoiceFunctionKeyLatch` 已引用计数各 owner，所以不能断言任一通道松开必然释放另一通道的键；音频混用仍是独立的真实缺口。 |
| 2 测试音异步竞态 | 成立。音频配置回调现在重新检查语音活动、已播放测试音及当前设备可用性；包括按键仍在激活、isStreaming 尚未发布的阶段。测试模拟语音在回调前获得通道。原有 `releaseVirtualAudioOutputIfUnused` 会检查活动来源，因此“测试音结束必然强关活动引擎”的说法不成立。 |
| 3 应用切换器取消 | 成立。cancel 先发送带 Command 的 Escape down/up，再释放 Command；confirm 只释放 Command。保留失败时的修饰键所有权清理。测试核对取消和确认的事件顺序、flags、重复取消。 |
| 4 轻触 Fn | 首次脉冲前松开仍会触发脉冲的路径成立，已取消该待启动会话及过期回调。首次按下已经发出时仍按原有成对释放与停止流程清理。测试覆盖开始延迟前松开、旧回调及下一次正常按住。系统听写是否把特定间隔识别成常开，取决于用户的听写快捷键设置，未作为所有 Mac 的必然结果。 |
| 5 圆环 NaN/Infinity | 成立。拒绝非有限输入，转换 Int 前先限制步数；巨大有限值也不会越界。测试覆盖 NaN、正负 Infinity 和正负 greatestFiniteMagnitude。 |
| 6 圆环剩余运动 | 无上限余量成立，已将单次累计量限制为本次最多三步加两步余量，避免后续小动作重放过量旧运动。测试覆盖巨大输入、余量上限和反向。累加器本身没有自动定时消费机制，因此不能单凭该代码证明“手指离开后自动滚动数秒”。 |
| 7 未知 Consumer usage | 成立。仅在已验证结构的 report 2 中跳过未知 usage，保留已知键；未知键单独存在也能释放已知键。错误 report ID、空包、畸形长度仍被忽略。真实 monitor 测试覆盖已知键和未知键同包、已知键释放、畸形报告不误释放。 |
| 8 缓存目标重连 | 成立。失败缓存目标的 bypass 现在只消费一个 discovery pass；20 秒扫描 watchdog 的后续 pass 可重新使用保存的设备标识，避免等待永不出现的广播。保留失败退避与成功 reset。测试核对首次 bypass 和下一轮恢复，而非要求用户手动重置。 |
| 9 常用语兼容 | 已补齐 AX 树初始化，并加入经用户授权的临时剪贴板粘贴：终端、Web/Electron 及不支持直接写入的可编辑目标使用 Cmd+V。备份各项格式、检查焦点/安全状态、按 changeCount 尝试恢复并保留期间的新复制。对模糊的 AX 失败不重试，防止重复插入。UI 与隐私说明已更新；投递成功不等于第三方应用已提交文本，实际兼容性仍需验收。 |
| 10 输入法预编辑 | 不自动清除用户输入。在设备准备文档说明先确认选词或手动 Escape，再开始语音；候选框存在时，方向键/Return 的选词行为属于正常键盘语义。未实现未经跨输入法验证的全局 Marked Text 推断，也不盲发可能丢弃输入或关闭应用对话框的 Escape。 |
| 11 增益保存 | 重复序列化成立，已消除选中 profile 更新后 gainDB didSet 再保存同一数组，以及重复相同值的保存。测试模拟重复提交 120 次相同值，只发布一次 profile 更新，重建设置仍保存正确值。滑块本身已有 1 dB 步进，UserDefaults.set 也不等于立即同步磁盘写入；未证实“每秒 120 次全量磁盘写入”或需要全局防抖，保留即时持久化。 |
| 12 引导权限撤销 | 成立。remote、controls、audio、voiceTest 的继续条件及诊断统一优先检查控制方式需要的权限；撤销后返回权限缺失原因和现有权限修复卡片入口。独立的工具配置和设备选择仍可使用；complete 原有回归恢复逻辑保留。测试逐步覆盖权限撤销覆盖其他诊断并恢复到 permissions。 |
| 13 Swift 6 | 尾随闭包歧义用独立 Swift 6 typecheck 最小样例复现。三个生产调用均显式传 completion，改后相同形式通过 Swift 6 typecheck。项目整体仍按现有语言模式构建，未宣称已完成 Swift 6 迁移。HIDPermissionPoll 的订阅状态已有 NSLock，AppLogger 的可变日志状态由串行 queue 保护，不能把缺少 Sendable/actor 声明直接等同于没有同步。 |
| 14 权限轮询能耗 | 每秒轮询确实存在，但其职责包括发现权限撤销及恢复，并在最后一个订阅取消时停掉。授权成功就永久停止会破坏持续检测；本轮保留。未提供能耗测量支持“阻止最深 C-State”的结论，不能将一次周期唤醒等同于持续阻止休眠。可在有完整撤权通知替代与能耗数据后再调整。 |
| 15 音频 sync 死锁 | 未确认实际锁环。stop 的主线程路径已异步；deinit 和 stop 均检查 engineQueue key，避免队列自同步。私有状态锁不跨 AV/HAL 调用持有，当前主线程请求的 drain 完成回调及配置恢复也异步回主队列。未找到清单所说的调用方持锁反向等待路径，因此未把同步析构机械改成捕获正在析构 self 的异步任务，也未削弱析构释放资源的保证。 |

## 验证

- `swift build --disable-keychain` 成功。
- `swift test --disable-keychain`：370 项测试、57 个 suite 通过。
- 全部 13 组 `scripts/test-*.py` 检查通过。
- 中英 Localizable.strings 的 plutil 检查通过，`git diff --check` 通过。
- Swift 6 typecheck 仅验证尾随闭包匹配这一隔离问题，不代表整个工程已支持严格并发模式。
- 真正的双遥控器、睡眠中的 BLE 重连、系统听写快捷键和第三方编辑器兼容性仍需实机验收。测试未改动真实权限、剪贴板或向用户应用发送按键。
